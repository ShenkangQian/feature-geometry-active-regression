# Reproducing the experiments

Run commands from the repository root. Install the package with `python -m pip install -e '.[test]'` or set `PYTHONPATH=src` and use `python -m geometa.cli`.

## Configurations

| Configuration | Purpose |
|---|---|
| `configs/smoke.yaml` | Small end-to-end check of pulse and chain tasks |
| `configs/smoke-fantasy.yaml` | Finite-mixture fantasy acquisition check |
| `configs/smoke-sweep.yaml` | Small mechanism-analysis pipeline check |
| `configs/local.yaml` | Two-seed exploratory pulse and chain experiment |
| `configs/sweep.yaml` | Five-seed, single-variable translation and width sweep |
| `configs/paper.yaml` | Larger task and inference budgets; no recorded run is included |

```bash
geometa --config configs/smoke-fantasy.yaml --output outputs/fantasy
geometa --config configs/smoke-sweep.yaml --output outputs/mechanism-check
python scripts/analyze_mechanism.py outputs/mechanism-check
```

The CLI refuses to overwrite an existing metric file by default. `--resume` reuses trained checkpoints and regenerates evaluation; it does not resume a partially completed evaluation queue. `scripts/slurm.sh` runs the larger configuration as a CPU seed array. Set `GEOMETA_PYTHON` to the cluster environment's Python executable.

## Recorded data

`results/sweep-20260924/` contains the full five-seed synthetic sweep: 720 tasks, 15 settings, and 86,400 task/method/budget records. `results/local-final-20260911/` contains the preceding pulse-and-chain experiment: 30 tasks, eight settings, and 1,680 records.

The per-budget CSVs are gzip-compressed to keep the repository small. To reconstruct analysis inputs without overwriting the recorded tables:

```bash
python - <<'PY'
from pathlib import Path
import gzip
import shutil

source = Path("results/sweep-20260924")
target = Path("outputs/reanalyze-sweep")
shutil.copytree(source, target)
with gzip.open(target / "metrics.csv.gz", "rb") as inp:
    with (target / "metrics.csv").open("wb") as out:
        shutil.copyfileobj(inp, out)
PY
python scripts/analyze_mechanism.py outputs/reanalyze-sweep
```

Checkpoint weights and individual function-prediction files are regenerated by running the configuration. The release includes training summaries, split manifests, metric rows, and every aggregate comparison. `inspect_run.py` is intended for a newly completed run, where all generated run artifacts are available.

`source_manifest.json` records SHA-256 hashes of the computational modules used by each original run. The current package matches the sweep manifest; the earlier pilot predates the comparator and diagnostic additions. Environment JSON files record the original runtime. Timing fields depend on hardware and load. Task generation and query noise use deterministic hash-derived seeds.

The original pilot called the prior-mean expansion `linearized`; the current package and sweep call it `linearized_prior`. The sweep's `linearized` expands at the context-conditioned readout mean. Do not pool these labels across the two runs.

## Data provenance

All observations and function targets are simulated by `src/geometa/data.py`. No personal records, institutional data, private model weights, or third-party dataset copies are included. The stored split IDs identify generated tasks. The numerical chain oracle is checked against a direct complex solve.

The working manuscript is maintained separately. This repository contains the implementation, executable experiment definitions, and numerical record.

## Release verification

The public source copy passes all 15 automated tests. A fresh smoke run completed 120 metric rows across five tasks and eight settings. Artifact inspection verified disjoint training, validation, and test IDs, matching source hashes, and a generated learning-curve figure.
